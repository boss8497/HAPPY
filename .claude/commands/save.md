# 작업 저장 (문서 + 메모리 + 커밋)

현재 브랜치의 변경 사항을 정리해서 저장한다.

## 실행 순서

1. **git diff 분석** — 변경된 파일 파악 (스크립트, 에셋, 프리팹 분리)
2. **ARCHITECTURE.md / README.md 업데이트**
   - 변경된 시스템에 대응하는 기존 `.md` 파일이 있으면 내용 업데이트
   - 신규 시스템이라면 해당 폴더에 `ARCHITECTURE.md` 또는 `README.md` 생성
   - 문서에 포함할 것: 역할, 핵심 흐름, 데이터 구조, 주의사항
3. **메모리 저장** — `project` 또는 `feedback` 타입으로 관련 내용 저장
   - 기존 메모리가 있으면 업데이트, 없으면 신규 생성
   - MEMORY.md 인덱스 동기화
4. **git commit**
   - 한국어 커밋 메시지
   - 스크립트 변경 / 에셋 변경을 구분해서 명확하게 작성
   - `git status`로 변경 파일 확인 후 관련 파일만 스테이징

## 커밋 메시지 형식

```
<핵심 변경 내용 한 줄>

- 변경 항목 1
- 변경 항목 2
```

## 규칙

- 에셋 파일(.prefab, .asset)은 스크립트 변경과 같이 묶어서 커밋한다
- `*.meta` 파일은 대응하는 파일이 변경/추가됐을 때만 포함
- 커밋 전 `git status`로 untracked 파일 확인 필수
- PR 없이 main에 직접 push 금지 규칙 상기
